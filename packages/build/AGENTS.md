# Build Worker

Follow the [domain model](../../ARCHITECTURE.md#domain-model) and [build pipeline](../../ARCHITECTURE.md#build-pipeline) in ARCHITECTURE.md. Extend `CIWorkflow` from `@cloudflare/ci` and use its native runners, checkout, snapshots, and reporting. Prepare provisioning through the trusted `PROVISIONING` service binding with the event's repository SlateID and commit. Carry that prepared value through install/build → migrations → deployment → schedule provisioning. Platform owns actor and database selection; Build owns deployment ordering. Give migration execution the native build snapshot. Migration runs disable output snapshots because their result is database state; retain the native build snapshot behavior. The uncredentialed build packages `build/server` and `build/client` and uploads them to a Workflow-selected R2 object through a presigned PUT URL. A normal Workflow step owns a fresh native Sandbox with no checkout or restored snapshot, downloads through a separately signed GET URL, and materializes only compiled JavaScript modules and client assets through the image-owned Python extractor. Reject archive links and special files and use native `tarfile.data_filter` confinement. Write the complete platform-owned Wrangler configuration into a separate clean deployment directory; never merge authored configuration. Invoke the absolute, image-installed pinned Wrangler with `--no-bundle`, the canonical SlateID and the configured dispatch namespace. Only `ASSETS` is an upload-time resource binding; source-map upload is disabled. Keep Wrangler pinned and verify its serialized upload metadata through `--dry-run --outfile`, then inspect effective bindings on Cloudflare. The publisher must never create or upload secret bindings. Destroy the publishing Sandbox when the step finishes. Install schedules only after deployment succeeds. Disable automatic retries for the migration Workflow step; preserve the native error and partial database state when it fails. Keep the push subscription scoped to slate source storage and the service binding separate from user-authenticated HTTP APIs.

Use the shared repository-root `scripts/cloudflare.sh` build/deploy phases for deployment of this Worker, matching platform, dispatcher, and auth. Keep the Artifacts trigger, bindings, and runtime secret names in `wrangler.jsonc`; use native `secrets.required` for the secret names and Doppler for their values. Do not add package-specific deployment scripts or a `.dev.vars` deployment copy.

Verify provisioning through the existing service binding, following [platform guidance](../platform/AGENTS.md#remote-resources-for-integration-tests). Keep `env.test` free of an Artifacts push subscription and target `contextlayer-platform-test`'s `Provisioning` entrypoint. Keep the test `BACKUP_BUCKET` binding remote so native snapshot uploads, verification and restoration address the same test bucket. Declare `CF_TOKEN`, `R2_ACCESS_KEY_ID` and `R2_SECRET_ACCESS_KEY` in `env.test.secrets.required`. The platform integration-test package script loads their test values from Doppler `platform/dev`; Wrangler’s native harness imports the declared process values. Leave CI deployment ownership with the deployed pipeline.

Manage `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `CF_TOKEN` centrally in Doppler and deliver only this Worker's required secrets through the shared deployment phase. Never print or commit their values. Let the CI SDK consume runtime variables and bindings directly from Wrangler configuration. Keep Cloudflare deployment credentials out of authored slate build commands. No CI runner opts into `cloudflareCredentials`. Pass `CF_TOKEN` only to the image-owned Wrangler command after artifact preparation in the fresh publishing Sandbox. Reusable R2 credentials stay in the Workflow; scoped URLs travel through runner/command environment variables and must not be printed.

Host native migration sandboxes in the existing `CiSandbox` namespace and expose the SDK's `ContainerProxy`. Register handlers by assigning `CiSandbox.outboundHandlers`, which invokes the native registry setter. Platform invokes that namespace through a cross-Worker Durable Object binding. The sandbox's outbound SQL handler uses only its trusted per-run instance selection and the `DATABASES` binding; authored requests supply SQL and parameters, never physical database identity. Preserve SQL errors across the HTTP boundary so the native Kysely CLI fails visibly.
