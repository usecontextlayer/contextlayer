# Build Worker

Follow the [domain model](../../ARCHITECTURE.md#domain-model) and [build pipeline](../../ARCHITECTURE.md#build-pipeline) in ARCHITECTURE.md. Extend `CIWorkflow` from `@cloudflare/ci` and use its native runners, checkout, snapshots, and reporting. Prepare provisioning through the trusted `PROVISIONING` service binding with the event's repository SlateID and commit. Carry that prepared value through install/build → migrations → deployment → schedule provisioning. Platform owns actor and database selection; Build owns deployment ordering. Give migration execution the native build snapshot and chain the deploy runner from that same build result. Migration runs disable output snapshots because their result is database state; retain the native runner’s normal snapshot behavior for build and deployment. Invoke Wrangler for server code and static assets, using the repository SlateID as the Worker name in the `contextlayer-prod` dispatch namespace. Install schedules only after deployment succeeds. Keep the push subscription scoped to slate source storage and the service binding separate from user-authenticated HTTP APIs.

Use the shared repository-root `scripts/cloudflare.sh` build/deploy phases for deployment of this Worker, matching platform, dispatcher, and auth. Keep the Artifacts trigger, bindings, and runtime secret names in `wrangler.jsonc`; use native `secrets.required` for the secret names and Doppler for their values. Do not add package-specific deployment scripts or a `.dev.vars` deployment copy.

Verify provisioning through the existing service binding, following [platform guidance](../platform/AGENTS.md#remote-resources-for-integration-tests). Keep `env.test` free of an Artifacts push subscription and target `contextlayer-platform-test`'s `Provisioning` entrypoint. Leave CI deployment ownership with the deployed pipeline.

Manage `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `CF_TOKEN` centrally in Doppler and deliver only this Worker's required secrets through the shared deployment phase. Never print or commit their values. Let the CI SDK consume runtime variables and bindings directly from Wrangler configuration. Keep Cloudflare deployment credentials out of authored slate build commands. Opt into the SDK's `cloudflareCredentials` capability only for the deploy runner, using the `CF_TOKEN` Worker secret.

Host native migration sandboxes in the existing `CiSandbox` namespace and expose the SDK's `ContainerProxy`. Register handlers by assigning `CiSandbox.outboundHandlers`, which invokes the native registry setter. Platform invokes that namespace through a cross-Worker Durable Object binding. The sandbox's outbound SQL handler uses only its trusted per-run instance selection and the `DATABASES` binding; authored requests supply SQL and parameters, never physical database identity. Preserve SQL errors across the HTTP boundary so the native Kysely CLI fails visibly.
