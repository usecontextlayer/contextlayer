# Build Worker

Follow the [domain model](../../ARCHITECTURE.md#domain-model) and [build pipeline](../../ARCHITECTURE.md#build-pipeline) in ARCHITECTURE.md. Extend `CIWorkflow` from `@cloudflare/ci` and use its native runners, checkout, snapshots, and reporting. Chain the install/build runner to the deploy runner using the SDK snapshot. Invoke Wrangler for server code and static assets, using the repository SlateID as the Worker name in the `contextlayer-prod` dispatch namespace. Only after deployment succeeds, call platform's `Provisioning.provision` through the native `PROVISIONING` service binding in a Workflow step. Pass only the repository SlateID; platform owns reading declarations and provisioning the slate for its actors. Keep the push subscription scoped to slate source storage and the service binding separate from user-authenticated HTTP APIs.

Use the shared repository-root `scripts/cloudflare.sh` build/deploy phases for deployment of this Worker, matching platform, dispatcher, and auth. Keep the Artifacts trigger, bindings, and runtime secret names in `wrangler.jsonc`; use native `secrets.required` for the secret names and Doppler for their values. Do not add package-specific deployment scripts or a `.dev.vars` deployment copy.

Verify provisioning through the existing service binding, following [DEVELOPING.md](../../DEVELOPING.md#remote-resources-for-integration-tests). Keep `env.test` free of an Artifacts push subscription and target `contextlayer-platform-test`'s `Provisioning` entrypoint. Leave CI deployment ownership with the deployed pipeline.

Manage `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `CF_TOKEN` centrally in Doppler and deliver only this Worker's required secrets through the shared deployment phase. Never print or commit their values. Let the CI SDK consume runtime variables and bindings directly from Wrangler configuration. Keep Cloudflare deployment credentials out of authored slate build commands. Opt into the SDK's `cloudflareCredentials` capability only for the deploy runner, using the `CF_TOKEN` Worker secret.
