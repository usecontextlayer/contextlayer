# Build Worker

Follow the [domain model](../../ARCHITECTURE.md#domain-model) and [build pipeline](../../ARCHITECTURE.md#build-pipeline) for ownership, phase ordering and credential boundaries. Extend `CIWorkflow` from `@cloudflare/ci`; use its native checkout, runners and snapshots. Own publication through a normal Workflow step and the native Sandbox lifecycle. Each publishing attempt must destroy its Sandbox when finished.

Keep publishing tools in the platform image and invoke its pinned Wrangler by absolute path with an explicit config and `--no-bundle`. Do not discover tools or configuration from artifact contents. Supply an explicit platform-owned tsconfig alongside the Wrangler config; authored compiler configuration must not control publication or filesystem reads. Use image-owned rclone for the R2 folder transfer, with its configuration supplied by platform code rather than a discovered config file. Download into a payload child of the clean execution root; keep the platform config outside that payload and do not enable link restoration. Keep source-map discovery disabled during publication; artifact-controlled paths must not make publishing tools read outside the selected module tree. When changing Wrangler or artifact preparation, verify effective bindings on Cloudflare as well as the serialized upload: upload metadata alone does not establish the resulting binding state.

Use the shared repository-root `scripts/cloudflare.sh` build/deploy phases for deployment of this Worker, matching platform, dispatcher, and auth. Keep the Artifacts trigger, bindings, and runtime secret names in `wrangler.jsonc`; use native `secrets.required` for the secret names and Doppler for their values. Do not add package-specific deployment scripts or a `.dev.vars` deployment copy.

Keep `env.test` free of an Artifacts push subscription. Its `BACKUP_BUCKET` must address the same remote bucket as snapshot upload, or upload verification and restoration will read a different store. [Platform test guidance](../platform/AGENTS.md#slate-build-verification) owns live pipeline prerequisites and commands.

No CI runner may opt into `cloudflareCredentials`. Scope deployment credentials to the image-owned Wrangler command after artifact preparation. Keep the parent R2 credential pair in the trusted Worker and derive temporary transfer credentials with Cloudflare's native prefix and permission scopes. Never print or commit credentials, including temporary session tokens.

Host native migration sandboxes in the existing `CiSandbox` namespace and expose the SDK's `ContainerProxy`. Register handlers by assigning `CiSandbox.outboundHandlers`, which invokes the native registry setter. Platform invokes that namespace through a cross-Worker Durable Object binding. The sandbox's outbound SQL handler uses only its trusted per-run instance selection and the `DATABASES` binding; authored requests supply SQL and parameters, never physical database identity. Preserve SQL errors across the HTTP boundary so the native Kysely CLI fails visibly.

## Artifact verification

Run `pnpm exec turbo run tsc test build --filter=@usecontextlayer/build` from the repository root. Building the Sandbox image requires Docker. Use the production transfer and publisher code in verification rather than maintaining a second artifact pipeline in test helpers.

The native Wrangler unit test verifies that authored configuration and modules cannot control or execute during publication. The R2 integration test calls the production temporary-credential generator and verifies allowed object access and an explicit authorization rejection outside the Workflow prefix. Run `pnpm exec turbo run test:integration:node --filter=@usecontextlayer/build`; its package script loads the test bucket credentials from Doppler `platform/dev` and selects the native Wrangler `test` configuration. It requires R2 network access and `R2_ACCESS_KEY_ID`/`R2_SECRET_ACCESS_KEY`, creates only uniquely named test objects, and deletes them on completion. It needs neither Docker nor Postgres.
