# Build Worker

This package runs the Artifacts push-to-build pipeline on Cloudflare. Extend `CIWorkflow` from `@cloudflare/ci` and use its native runners, checkout, snapshots, and reporting. The pipeline chains an install/build runner to a deploy runner using the SDK snapshot. The deploy runner invokes Wrangler for both server code and static assets, using the repository AppID as the Worker name in the contextlayer-prod dispatch namespace. After deployment succeeds, a native Workflow step calls the platform's named `Publication` WorkerEntrypoint through `PUBLICATION`, passing only the repository AppID so shared platform setup reads the latest coherent declaration snapshot, provisions folders for joined members and registers schedules. Keep the push subscription scoped to app-source storage; document folders live in a separate Artifacts namespace. Keep this trusted native service binding separate from user-authenticated HTTP APIs. There is no ContextLayer build UI.

Use the shared repository-root `scripts/cloudflare.sh` build/deploy phases for deployment of this Worker, matching platform, dispatcher, and auth. Keep the Artifacts trigger and resource declarations together in `wrangler.jsonc`. Native `secrets.required` owns this Worker's runtime secret names; Doppler owns their values. Do not add package-specific deployment scripts or a `.dev.vars` deployment copy.

Local publication verification selects native env.test for both build and platform and uses their normal production bundles. The test PUBLICATION binding targets contextlayer-platform-test’s Publication entrypoint; Artifacts uses contextlayer-test, while the harness owns local R2, Workflow, Durable Object, and container state. This test configuration has no Artifacts push subscription. Verify registration through the existing service binding, leaving CI deployment ownership with the production pipeline.

Manage `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, and `CF_TOKEN` centrally in Doppler and deliver only this Worker's declared secrets through the shared deployment phase. Never print or commit their values. Runtime variables and bindings belong in the Wrangler configuration; the CI SDK consumes them directly. Authored-app build commands receive no Cloudflare deployment credential. Only the authored-app deploy runner opts into the SDK’s `cloudflareCredentials` capability, which reads the `CF_TOKEN` Worker secret.
