# Dispatcher

Use Wrangler for this Worker, as explicitly approved alongside `packages/build`. The platform owns the hostname-to-AppID mapping. Send the incoming hostname and URL pathname to its OpenAPI resolution endpoint, validate the response with Zod, and forward the original request using the native dispatch namespace binding. The AppID is the WfP Worker name. Do not add a local mapping, cache, or database connection.

`CTX_PLATFORM_URL` points to the deployed platform at `https://slate.usecontextlayer.com`; no local tunnel is required. Use `env.ts` for environment-variable validation. Forward the incoming Authorization header and existing `ctx-viewer-auth` cookie to platform's resolution endpoint. Platform owns identity verification and public/private viewing decisions. Dispatch on 200, redirect 401 to the existing auth `/start` with `return_to`, and forward other failures. Ordinary browser paths, including `/slate.json`, use this resolution. MCP has the explicit bearer-only boundary below. Strip Authorization and the viewer cookie before invoking authored code. Do not add dispatcher session verification, visibility logic, or membership checks.

## Viewer capabilities

After successful resolution, requests carrying a viewer cookie receive the exported `Tools` capability through Cloudflare’s native loopback exports, configured with the resolved AppID and typed viewer-session credential in native props. The hosted class comes from `@usecontextlayer/shared/tools-worker` and accepts only the viewer-session credential. The SDK local Worker exports the separate `LocalTools` class from that same module: trusted CLI construction selects the app consumer from assembled local configuration and supplies only its resolved connections and CLI access token. Local Tools uses the personal concrete-account API; hosted Tools uses the pushed-declaration slug operation through the native EXECUTION service binding. Share result/error semantics without a mode flag, optional declarations, or interchangeable credential authority; hosted execution uses the shared typed `HostedExecution` result contract while local execution retains its personal-account HTTP contract. Pass that RPC stub in dynamic-dispatch `props.tools`. The separate `Databases` class from `@usecontextlayer/shared/databases-worker` binds the same resolved AppID and viewer-session credential; pass its RPC stub in native `props.databases`. It forwards declared-slug SQL queries to the platform's authorized database operation without exposing credentials, namespace access, or migration setup to authored code. The Tools and Databases entrypoints call platform’s separate Execution WorkerEntrypoint through EXECUTION, passing AppID, the viewer session token as data, and the call. Bind production to contextlayer-platform and test to contextlayer-platform-test. The binding supplies invocation authority; platform verifies session identity and applies viewing, subscription and resource policy. Viewer-mode resources require app membership and owner-mode resources require viewing. Platform owns the membership lookup per delegated call; the hosted capabilities turn its typed `membership-required` and `not-declared` outcomes into ordinary `Error` objects with those exact messages for app code. No cookie header or public execution URL belongs in these hosted entrypoints. User code receives neither the session token nor an AppID parameter it can change. Requests without a viewer cookie receive empty props. `cloudflare.d.ts` declares the main module for Cloudflare’s typed loopback exports.

Platform also checks the app owner’s saved Polar subscription before runtime dispatch. Exactly `/slate.json` retains viewing authorization but skips billing. Forward the incoming URL pathname, not a caller-supplied override. Subscription denial is 402 and follows the existing failure forwarding; dispatcher has no subscription policy; it uses Polar’s SDK only to report executed usage. Hosted Tools calls reach the platform’s same subscription gate separately.

## App usage

Resolution returns the canonical `{ id, owner }` through `resolvedAppSchema` in `@usecontextlayer/shared/app-usage`. After dispatch returns, use that module’s `appRequestUsage` and `recordAppUsage`: recognised dynamic GETs cost one clip, POST/PUT/PATCH/DELETE cost three, and `/slate.json` is free. Best-effort response classification recognises HTML, JSON (including application `+json`), React Router `text/x-script`, plain text, CSV, XML, NDJSON, event streams and redirects. JavaScript, CSS, images, fonts and WebAssembly media types generate no event for these methods. Classification depends on app-controlled response headers and is deliberately not an unbypassable static/runtime distinction; owner attribution and event weights remain trusted. No SDK instrumentation or app reporting callback owns billing. Schedule native Polar ingestion with `executionCtx.waitUntil`, then return the app response without awaiting delivery. Both `POLAR_ACCESS_TOKEN` and `POLAR_ENVIRONMENT` are required Worker bindings, validated by `env.ts`; authored code receives neither them nor the owner metadata.

## MCP

Register public `/.well-known/oauth-protected-resource/mcp` and exactly `/mcp` before the browser wildcard. Metadata is read from platform’s canonical app metadata operation without caller credentials. MCP resolution forwards only the explicit Authorization header, with the actual hostname and `/mcp` pathname; never forward viewer or native web cookies. Platform verifies the exact app audience and `ctx:mcp` scope, then applies existing viewing and subscription policy. Forward native OAuth challenges and failures without browser-login redirects. After resolution succeeds, `/mcp` uses `serveMcp` and the native MCP SDK HTTP lifecycle. Discover tools and Views from the generated `/mcp.json` and static View assets through `APPS`; never import or evaluate author modules in trusted code. Use the native MCP Apps registration helpers and shared artifact schema, with no custom JSON-RPC implementation. Artifact reads and tool execution requests must not forward caller credentials into authored code.

Invoke a named tool by supplying `mcpTool` in native dispatch props and validated JSON arguments. Validate the returned native tool result, then schedule one shared `tool_call` event through `waitUntil`. MCP discovery and resource reads must not also pass through ordinary HTTP action/loader metering. Consumer resource restrictions belong to the canonical Slate model; never substitute the app's full Tools capability for a tool's declared subset.

## Chrome reads

Profile and connection reads belong to platform’s trusted iframe. Dispatcher exposes Tools and Databases capabilities to authored code; it has no Viewer or Connections entrypoints, chrome rendering, or profile/assignment database access.
