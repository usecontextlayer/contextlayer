# Dispatcher

Use Wrangler for this Worker, as explicitly approved alongside `packages/build`. The platform owns the hostname-to-AppID mapping. Send the incoming hostname and URL pathname to its OpenAPI resolution endpoint, validate the response with Zod, and forward the original request using the native dispatch namespace binding. The AppID is the WfP Worker name. Do not add a local mapping, cache, or database connection.

`CTX_PLATFORM_URL` points to the deployed platform at `https://slate.usecontextlayer.com`; no local tunnel is required. Use `env.ts` for environment-variable validation. Forward the incoming Authorization header and existing `__Secure-ctx_viewer` cookie to platform's resolution endpoint. Platform owns identity verification and public/private viewing decisions. Dispatch on 200, redirect 401 to the existing auth `/start` with `return_to`, and forward other failures. Every path, including `/slate.json`, uses this same resolution. Strip Authorization and the viewer cookie before invoking authored code. Do not add dispatcher session verification, visibility logic, or membership checks.

## Viewer tools

After successful resolution, requests carrying a viewer cookie receive the exported `Tools` capability through Cloudflare’s native loopback exports, configured with the resolved AppID and viewer session token. Pass only that RPC stub in dynamic-dispatch `props.tools`. The entrypoint forwards calls to the platform’s existing tool-execution API using the viewer cookie; that API verifies its own authentication. User code receives neither the session token nor an AppID parameter it can change. Requests without a viewer cookie receive empty props. `cloudflare.d.ts` declares the main module for Cloudflare’s typed loopback exports.

Platform also checks the app owner’s saved Polar subscription before runtime dispatch. Exactly `/slate.json` retains viewing authorization but skips billing. Forward the incoming URL pathname, not a caller-supplied override. Subscription denial is 402 and follows the existing failure forwarding; dispatcher has no subscription policy; it uses Polar’s SDK only to report executed usage. Hosted Tools calls reach the platform’s same subscription gate separately.

## Viewer profile

Requests carrying a viewer cookie also receive the exported Viewer capability through native loopback exports in props.viewer. It calls web's /api/me directly using that session cookie and returns only the Zod-validated id, name, and nullable image; 401 returns null and other failures propagate. CTX_AUTH_ISSUER defaults to https://www.usecontextlayer.com/api/auth in env.ts. Web owns identity verification and the profile read. Do not proxy profile data through platform or expose the session token to the app. Anonymous requests retain empty props; the SDK's native React Router viewerContext default returns null. This wiring is implemented but has not been deployed or exercised through hosted WfP yet.

## App usage

Resolution returns the canonical `{ id, owner }` through `resolvedAppSchema` in `@usecontextlayer/shared/app-usage`. After dispatch returns, use that module’s `appRequestUsage` and `recordAppUsage`: recognised dynamic GETs cost one clip, POST/PUT/PATCH/DELETE cost three, and `/slate.json` is free. Best-effort response classification recognises HTML, JSON (including application `+json`), React Router `text/x-script`, plain text, CSV, XML, NDJSON, event streams and redirects. JavaScript, CSS, images, fonts and WebAssembly media types generate no event for these methods. Classification depends on app-controlled response headers and is deliberately not an unbypassable static/runtime distinction; owner attribution and event weights remain trusted. No SDK instrumentation or app reporting callback owns billing. Schedule native Polar ingestion with `executionCtx.waitUntil`, then return the app response without awaiting delivery. Both `POLAR_ACCESS_TOKEN` and `POLAR_ENVIRONMENT` are required Worker bindings, validated by `env.ts`; authored code receives neither them nor the owner metadata.

## App connection reads

Requests carrying a viewer cookie also receive the Connections loopback RPC stub in props.connections, bound to the resolved AppID and viewer session. Its list method calls the existing platform app-connection listing operation with an empty body and returns only requirement/assignment rows validated through @usecontextlayer/shared/app-connections. Platform owns authorization, fetching the deployed manifest, and reading assignments. Dispatcher has no connection-selection rules or database access. The SDK root loader consumes this read; SDK owns the connection-section trigger and JSON tray. Hosted runtime verification is pending.
