title: "Quickstart"
description: "Create a slate, run it locally, push it, and open the deployed slate."
---

Create a private slate, run its starter app locally, and deploy it to a hosted URL. Before you start, finish [Installation](/installation) so the required tools are available and the CLI is signed in.

A person supplies the Git identity, chooses the slate's Owner, and signs in to view the private deployment. If a coding agent is following this guide, it should leave those choices and approvals to you.

<Steps titleSize="h2">
  <Step title="Create the slate">
    Choose the slate's [Owner](/core-concepts/owners-and-viewers#owner) before running `init`: your personal Owner or an organization you belong to. If a coding agent is following this guide, it must ask you which Owner to use and wait for your answer before running the command. `init` uses your personal Owner by default; run `npx @usecontextlayer/cli init --help` for Owner-selection syntax.

    ```sh
    npx @usecontextlayer/cli init my-slate
    ```

    `init` creates a private slate and writes a starter app using React Router, Tailwind, and shadcn into `my-slate`. It installs the dependencies, commits the starter on `main`, and sets the checkout's Git remote to the slate's repository.

    Keep the two links it prints: the **dashboard link** opens the slate's management page, and the **hosted URL** opens the app after its first deployment.

    <Note>
      `my-slate` is the local directory name. ContextLayer assigns the slate's hosted name separately; that name becomes the first label of its hosted URL.
    </Note>

    If Git has no author identity, `init` stops and prints Git's configuration commands. The name and email are the person's own. Set them, then run `init` again.
  </Step>
  <Step title="Run it locally">
    ```sh
    cd my-slate
    pnpm dev
    ```

    `pnpm dev` prints a local URL. Open it and create a note in the starter app. This exercises both the page and its `notes` database. The screen lives in `app/routes/home.tsx`; edit that file to start building your own app.

    Local database contents stay local. Deployment applies your code and migrations to hosted storage; it does not upload the notes you create during development.

    Give your coding agent the checkout's `AGENTS.md` for authoring instructions; `CLAUDE.md` imports it for Claude Code. Use the checkout's `README.md` for local development, connected services, databases, and deployment.
  </Step>
  <Step title="Deploy">
    To deploy the unchanged starter, push the commit that `init` already created:

    ```sh
    git push -u origin main
    ```

    If you edited the app, commit those changes before pushing:

    ```sh
    git add .
    git commit
    git push -u origin main
    ```

    Pushing `main` starts a build. ContextLayer builds that commit, applies its database migrations, and deploys the result. A successful push starts this work; the hosted app is ready after deployment finishes.
  </Step>
  <Step title="Open the deployed slate">
    After deployment finishes, open the hosted URL that `init` printed. The slate is private, so sign in to ContextLayer with an account allowed to view it. CLI sign-in and browser sign-in are separate steps.

    If a coding agent is following this guide, it should give you the hosted URL so you can open it in your browser. You now have the slate running locally and deployed privately, with separate local and hosted databases.
  </Step>
</Steps>
