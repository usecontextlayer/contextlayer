ContextLayer is a platform for building software around the way you work. Write TypeScript, React, and SQL in your editor, with your coding agent, and let ContextLayer host the result.

Your software lives in a **slate**: a durable Git repository that starts without an app, static content, agents, or MCP tools. Add the parts you need, bit by bit, as ordinary editable source, then push to deploy them together. The repository holds code, build configuration, and resource declarations; connected-account credentials, secret values, and database contents live outside Git.

You might begin with an app that stores notes, then add an agent that summarizes the notes people have already written. The agent works with data the app already stores, within the same slate. The [Slate guide](/core-concepts/slate#how-the-parts-work-together) explains how its parts work together through shared data, source code, and serving rules.

## What is in a slate

A slate can combine these parts, or contain just one:

- The [**app**](/core-concepts/slate/app) is the browser interface people use to view information and take actions. It is built with React Router.
- **Static files** in `public/` provide pages and assets with or without an app. They follow the slate's viewing permissions.
- [**Agents**](/core-concepts/slate/agents) are named sets of standing instructions that accept input in hosted conversations, on demand or on a schedule.
- [**MCP tools and Views**](/core-concepts/slate/mcp) provide tools for Model Context Protocol clients and browser UI source built alongside the rest of the slate.
- [**Resources**](/core-concepts/resources) are the connections, databases, and secrets the app and agents use. Each app or agent declares its requirements in a `slate.json` file.

Use scaffolding for a starting point, or write the source directly; the files have the same meaning either way. The [Slate guide](/core-concepts/slate#create-a-slate) explains starting empty and adding source.

## Connections, accounts, and assignments

These three terms describe different parts of connecting a slate to an external service:

- A **connection** declares what the slate needs, such as a Gmail connection named `inbox`.
- An **account** is a connected account, such as your Gmail account. It belongs to a person or organization independently of any slate.
- An **assignment** selects the account that satisfies a connection.

Declaring `inbox` says that the slate needs Gmail access. Assigning your connected Gmail account to `inbox` tells ContextLayer which account to use. See [Connections and assignments](/core-concepts/resources/connections-and-assignments) for how this works locally and after deployment.

## Owners and viewers

An **Owner** is the personal or organization identity that owns a slate or resource. A **viewer** is a person using the slate. Ownership and viewing access answer different questions: who manages the slate, and who can use it.

A declared resource's **mode** selects whose resource the hosted slate uses:

| Mode | Resource Owner | Example |
| --- | --- | --- |
| `owner` | The slate's Owner | A shared database of customer requests. |
| `viewer` | The person using the slate | Each person's own Gmail account. |

One slate can combine both modes. Everyone can work with the same request database while each person uses their own inbox. See [Owners and viewers](/core-concepts/owners-and-viewers) for access rules and resource ownership.

## Working with a coding agent

The same documentation is available to you and your coding agent:

- **Read a page as Markdown.** Add `.md` to its URL, as in [the quickstart's Markdown view](/quickstart.md).
- **Find relevant pages.** The [documentation index](https://docs.usecontextlayer.com/llms.txt) lists pages and descriptions.
- **Install the ContextLayer skill.** Give your agent the product's capabilities and workflows with the skills CLI:

```sh
npx skills add https://docs.usecontextlayer.com
```
