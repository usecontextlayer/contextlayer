# Architecture

The repository contains seven private packages:

- `cli` — Commander-based `ctx` executable, bundled with tsdown; its version comes from its package manifest, and `init` delegates project creation to the official `create-cloudflare@latest` React Router scaffold.
- `db-infra` — Postgres/Kysely connections, migrations, and ephemeral database helpers.
- `shared` — Authentication, token handling, test helpers, and Sentry event capping.
- `twilio` — Twilio Functions for founder call routing and answer screening.
- `platform` — Cloudflare Workers application: an Artifacts Git proxy under `/git`, OpenAPI endpoints under `/api`, and the React Router dashboard under `/dashboard`.

- `build` — Cloudflare Worker using `@cloudflare/ci` and Workflows to build commits pushed to Artifacts in isolated Sandbox runners.

- `dispatcher` — Cloudflare Worker that resolves public hostnames through the platform API and invokes the WfP Worker named by AppID.

## Platform storage and request flow

The dashboard uses shadcn/ui with the `base-nova` preset and standard Tailwind layout utilities.

Hono middleware creates a request-scoped Postgres.js/Kysely connection from validated Worker bindings and passes through the native Artifacts binding. API handlers and React Router loaders share these through their framework contexts; `waitUntil` closes the database after the handler finishes. The Cloudflare Vite plugin runs development in workerd and builds the Worker plus client assets. The platform's `app` table contains `id` (UUID primary key, generated by Postgres) and `public_hostname` (text with a unique index). App identity is immutable; the public hostname is independent. Package-owned Kysely migrations and Kanel-generated models follow the retained `db-infra` patterns, using a separate logical database on the shared local Postgres instance.

`POST /api/apps` calls `createApp()`, which generates a friendly adjective/color/animal hostname, inserts the app, and creates an Artifacts repository named by its UUID. `ctx init` calls this endpoint after scaffolding and sets `/git/<app-id>` as the project's remote. `GET /api/apps` and the dashboard loader call the shared `listApps()` operation, which reads platform app records and the latest main-branch commit from each Artifacts repository. Commit hashes remain Cloudflare-owned data; the dashboard displays seven characters. Zod defines API contracts, with OpenAPI at `/api/openapi.json`.

`GET /api/apps/resolve?hostname=<public-hostname>` validates the hostname with Zod and calls `resolveApp()`, which looks up the unique `app.public_hostname` and returns `{ "id": "<app-id>" }`. An unassigned hostname returns HTTP 404. The dispatcher uses this lookup contract; the platform owns the mapping.

Git clients use the immutable `/git/<app-id>` endpoint. Git routes validate the ID, check the platform app record, obtain repository-scoped Artifacts credentials, and use Hono's proxy helper to forward protocol traffic. Pushes do not create app records. Credentials stay server-side. Authentication is not implemented yet.

## Build pipeline

Artifacts push events in `contextlayer-dev` start the `contextlayer-build` Workflow. `packages/build/index.ts` subclasses the SDK’s `CIWorkflow` with a build runner (`pnpm install --frozen-lockfile && pnpm build`) followed by a chained deployment runner. The SDK checks out the event’s commit, captures logs and status, and retains the workspace snapshot in the `contextlayer-build-backups` R2 bucket. The official Sandbox image supplies the runtime; the package Dockerfile adds the workspace’s pnpm version.

The deployment runner restores the successful build workspace and invokes Wrangler to deploy the Worker and static assets into the `contextlayer-dev` dispatch namespace, using the Artifacts repository name (AppID) as the Worker name. Only this runner opts into the SDK’s `cloudflareCredentials` capability, backed by the `CF_TOKEN` Worker secret. Operators inspect both steps in Cloudflare’s Workflows dashboard. ContextLayer’s app dashboard does not expose build status yet. The build Worker uses Wrangler configuration and deployment as an approved exception to `cf`, whose new configuration does not yet support Artifacts event triggers.

## Hosted-app routing

`packages/dispatcher` owns the wildcard Worker route `*.contextlayer.xyz/*`. It passes the incoming hostname to the platform's `/api/apps/resolve` endpoint, validates the returned UUID, and forwards the original request to `APPS.get(id).fetch(request)`. `APPS` binds the `contextlayer-dev` WfP dispatch namespace. The platform database is the source of the hostname mapping; the dispatcher has no database or mapping cache.

The platform is deployed at `https://slate.usecontextlayer.com` with Neon Postgres configured through Doppler `platform/prod`. The dispatcher’s `CTX_PLATFORM_URL` points to that address; it no longer depends on a local server or tunnel. Existing local app records were intentionally not migrated. Wrangler builds and deploys the Workers.
